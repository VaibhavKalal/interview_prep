# 06 — Go, In Depth (Week 7)

**Why it matters:** Go is the dominant language for backend infrastructure (Kubernetes,
Docker, Terraform, most cloud tooling). Depth in Go concurrency is a strong senior signal.

## Checklist

### L1 — Use
- [ ] Slices (length vs capacity, `append` reallocation), maps, structs, methods, interfaces
- [ ] Error handling: wrapping (`fmt.Errorf("%w")`), `errors.Is`/`errors.As`, sentinel errors
- [ ] Packages, modules, visibility, project layout
- [ ] Testing: table-driven tests, subtests, benchmarks, `httptest`

### L2 — Internals
- [ ] Goroutines vs OS threads: stack size, growth, cost
- [ ] The GMP scheduler: G (goroutine), M (OS thread), P (processor); work stealing; `GOMAXPROCS`
- [ ] Channels: buffered vs unbuffered, closing rules, nil channel behavior, `select`
- [ ] The Go memory model: happens-before; why the race detector matters
- [ ] Escape analysis: stack vs heap allocation (`go build -gcflags=-m`)
- [ ] Garbage collector: concurrent tri-color mark-and-sweep, `GOGC`, `GOMEMLIMIT`
- [ ] Interfaces internally (type + value pair); the nil interface vs nil pointer trap

### L3 — Production
- [ ] `context.Context`: cancellation, deadlines, propagating through HTTP handlers and DB calls
- [ ] Concurrency patterns: worker pool, fan-out/fan-in, pipelines, `errgroup`, semaphore via buffered channel
- [ ] Goroutine leaks: causes (blocked sends, no cancellation) and detection
- [ ] `sync` package: `Mutex`, `RWMutex`, `Once`, `WaitGroup`, `Pool`
- [ ] Profiling with `pprof`: CPU, heap, goroutine profiles
- [ ] `net/http` server hardening: timeouts (`ReadHeaderTimeout` etc.), graceful shutdown with `Shutdown(ctx)`
- [ ] Structured logging with `log/slog`

## Lab (weekend, in `labs/06-go/`)

Build a small **URL-checker service**:
1. Accept a list of URLs over HTTP; check them concurrently with a worker pool of N goroutines.
2. Every check respects a per-request `context` deadline; cancel all work if the client disconnects.
3. Use `errgroup` with a concurrency limit.
4. Add graceful shutdown on `SIGTERM`.
5. **Break it:** remove cancellation and create a goroutine leak. Find it with `pprof`'s goroutine profile (`/debug/pprof/goroutine`).
6. Benchmark and profile it; find the top allocation with `pprof` and reduce it.

## Self-test
1. What happens when you send on a closed channel? Receive from one? Send on a nil channel?
2. Explain the GMP scheduler. What happens when a goroutine makes a blocking syscall?
3. Why can a function that returns a `nil` `*MyError` as an `error` make `err != nil` true?
4. How do you stop 1,000 goroutines cleanly when the first one fails?
5. When would you choose a mutex over a channel?
6. How would you find and fix a goroutine leak in production?
